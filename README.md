# Event Contract App

event-contract-app implements a Polymarket-style CLOB for event contracts on LightPool—trade Yes/No outcome shares on an on-chain order book, with CEX-smooth trading, no wallet popups on every order, and support for high-frequency bot trading. Educational and research use only — not for production.

```bash
mkdir -p lightpool-labs && cd lightpool-labs
git clone git@github.com:lightpool-labs/event-contract-app.git
cd event-contract-app
```

## Step 1

Install the toolchain. Tools that are already installed are skipped.

```bash
./scripts/download-toolchain.sh
```

## Step 2

Download the other repositories and build them. Repositories that are already cloned are skipped.

```bash
./scripts/download-and-build.sh
```

The script clones these repositories next to this app: `lightpool-node`, `lightpool-crypto`, `lightpool-sdk-rust`, `lightpool-clob-indexer`, `lightpool-bridge`, `lightpool-bot`, and `lightpool-tutorials`. It then downloads Reth and builds the node, indexer, bridge, liquidity maker, and app backend.

## Step 3

Start the local stack.

```bash
./scripts/start-events.sh start
```

Open http://127.0.0.1:3000

Stop:

```bash
./scripts/start-events.sh stop
```

Delete runtime data (stop first):

```bash
./scripts/start-events.sh clean
```

## Research: who signs, and can the agent key be stolen

Educational notes from local design review. Not a production threat model.

This app does **not** keep the agent key in the browser. papertrade and tokenized-stocks do.

### Who signs

| Action | Signer | MetaMask popup |
| --- | --- | --- |
| Login | User signs a nonce (SIWE-style). Backend stores a session token | Yes |
| `set_agent` | User MetaMask (EIP-712). Agent address was generated by the backend | Yes, once |
| place / cancel / mint-style user ops | Backend `agent_signer`: decrypts `agent_secret_encrypted` with `AGENT_ENCRYPTION_KEY` and signs | No |

The browser never sees the agent private key. Another open website cannot read it from `sessionStorage`, because it is not there.

### What can still be stolen

| Secret | Where | Who can use it |
| --- | --- | --- |
| Session token | Browser (this origin) | Anyone who can run script on this origin (XSS) or read DevTools can ask the backend to sign **as that user**, until the session expires. They do not get the raw key. |
| `AGENT_ENCRYPTION_KEY` + user DB row | Backend | An engineer or attacker who has both can decrypt every agent secret and sign without the user's browser. Default dev key is `dev-agent-encryption-key`. |

Encryption at rest does not stop someone who already has the encryption key and the database.

### Compared with browser agents

| | Browser agent (papertrade, stocks) | This backend agent |
| --- | --- | --- |
| Other websites | Cannot read the key | No key in the page |
| XSS | Steals the key | Steals the session; backend will still sign |
| Engineer with server access | Does not have user keys | Can decrypt keys if they have `AGENT_ENCRYPTION_KEY` |
| Must use the user's browser to sign an order | Yes | No, if they already have the secret or a live session |
